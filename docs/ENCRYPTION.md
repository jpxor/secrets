# How Secrets encrypts your vault

Secrets encrypts service names, usernames and secrets before saving or backing them up. This walkthrough describes [source revision b34074c](https://github.com/jpxor/secrets/tree/b34074c2770974addd4d9f5681671a59816e40f6); links point to the exact implementing lines. It explains the design, not a guarantee against every attack. The [security review](SECURITY_REVIEW.md) documents known plaintext-exposure gaps.

1. **Create a random vault key.** On creation, the app generates a 32-byte (256-bit) data key, a random vault ID and a 16-byte salt using secure randomness. The data key is independent of your passphrase. [Random generation](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L9-L12); [vault creation](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L148-L168).

2. **Derive a wrapping key from your passphrase.** Argon2id uses your passphrase and the salt with 19 MiB of memory, two iterations and one lane to produce another 32-byte key. This makes each password guess more expensive; a weak passphrase can still be guessed offline from a stolen backup. The master passphrase is not saved. [Key derivation](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L136-L146).

3. **Encrypt the vault key.** AES-256-GCM encrypts the random data key with the passphrase-derived wrapping key. GCM also produces an authentication tag so changes can be detected. The header is authenticated, with a `/key` label distinguishing this operation. [Key wrapping](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L169-L177); [authenticated header](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L58-L69).

4. **Encrypt every record together.** The app serializes all record fields into an in-memory JSON payload, then encrypts it with the random data key using AES-256-GCM and the `/payload` authentication label. The cryptography library generates a fresh random nonce for each encryption. Each encrypted object stores ciphertext, a 12-byte nonce and a 16-byte authentication tag. [Record fields](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L32-L37); [payload encryption](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L233-L257); [encrypted-object encoding](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L109-L123).

5. **Save or back up the encrypted envelope.** The portable file contains the public header, encrypted data key and encrypted payload. Android stores that envelope atomically; manual export and backup providers receive the envelope, not decrypted records. Background backup needs provider credentials but never needs your vault unlocked. [Envelope](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L70-L74); [save boundary](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/session.dart#L118-L128); [local persistence](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/android/app/src/main/kotlin/app/secretskeeper/secrets/LocalStore.kt#L38-L51); [export](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/android/app/src/main/kotlin/app/secretskeeper/secrets/MainActivity.kt#L288-L292); [backup upload](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/android/app/src/main/kotlin/app/secretskeeper/secrets/BackupEngine.kt#L7-L27).

6. **Unlock or recover using the passphrase.** The app checks format/size/KDF bounds, derives the wrapping key again, authenticates/decrypts the data key, then authenticates/decrypts the records. Record JSON is parsed only after successful authentication. Import replaces local state only after this succeeds. A valid backup and the correct passphrase work without the old phone. [Bounds](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L75-L105); [unlock](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L183-L229); [restore](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/session.dart#L131-L152).

7. **Optionally unlock with biometrics on this phone.** Android Keystore protects a separate, device-local encrypted copy of the same data key. A strong biometric must authorize the actual cipher operation. Fingerprint success alone is not an encryption key. This binding is excluded from portable exports, so recovery still needs the passphrase. [Binding and biometric decryption](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/android/app/src/main/kotlin/app/secretskeeper/secrets/MainActivity.kt#L202-L253).

8. **Drop decrypted session state when locking.** Locking overwrites the owned session-key buffer, drops record references and closes unlocked routes. Managed-runtime strings and other temporary copies cannot be guaranteed erased from RAM. [Lock](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/session.dart#L179-L185); [key cleanup](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/core/vault.dart#L125-L133); [route cleanup](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/lib/app.dart#L50-L57).

Encryption protects stored content, not everything around it. File size, vault ID and backup timing remain visible. Unlocked text reaches the screen/keyboard; copying gives plaintext to Android's clipboard. Default selection controls currently permit additional copy and external-app actions (see the review). A compromised device can observe unlocked data, and an intact older backup can be replayed. There is no passphrase reset. See the [byte-level format](VAULT_FORMAT.md), [security boundaries](SECURITY.md) and [tests](https://github.com/jpxor/secrets/blob/b34074c2770974addd4d9f5681671a59816e40f6/test/vault_test.dart#L8-L96) for details you can check yourself.
