Privacy policy

Effective October 20, 2026 · Applies to the official Secrets Android application and this project website.

Who operates Secrets

Secrets is an open-source project maintained through jpxor/secrets on GitHub. The maintainer operates no application backend or vault storage service. For privacy questions, use GitHub Issues without including private information. For a suspected vulnerability, follow the repository's security reporting policy.

What stays on your phone

Service names, usernames and secrets are stored as an encrypted vault in app-private storage. The master passphrase is used to unlock the vault and is not saved. Decrypted records and keys are present in memory while unlocked; complete erasure from managed memory cannot be guaranteed. Clipboard copies temporarily expose the chosen value to the operating system and applications with clipboard access.

Optional biometric unlocking uses Android's biometric prompt and device Keystore. Secrets does not receive or store fingerprint templates. Biometric success alone is not a portable encryption key. Backup configuration and any stored provider credentials are protected separately using the device Keystore so encrypted backups can run while the vault is locked.

Optional Google Drive access

If you connect Google Drive, Secrets uses Google Play services for account authorization and requests only https://www.googleapis.com/auth/drive.appdata. This permits creating, listing, downloading and deleting Secrets backup files in its private application data folder; Secrets does not request general access to your Drive documents.

Secrets sends encrypted vault snapshots and backup metadata needed to identify and order them. Your passphrase, decrypted records and device biometric keys are not uploaded. Google processes authorization information and network/service metadata such as account identity, IP address, request times and file sizes under its own privacy policy. The maintainer receives no copy of your Google account tokens or backups.

Secrets uses Google API data only to provide the backup and restore features you choose. It does not sell Google user data, use it for advertising, or transfer it to the maintainer. Secrets' use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

Optional SFTP backups and manual exports

If you configure SFTP, Secrets connects to the server you select and sends encrypted snapshots and backup filenames/metadata. The server receives connection/authentication information and may record your username, IP address, file sizes and times. Its operator controls its logs and retention. Secrets verifies the configured SSH host-key fingerprint.

Manual exports save encrypted files to a location or document provider you choose through Android. That destination may itself upload files or retain copies under its own policies. Protect your export files and passphrase separately.

Retention, deletion and revoking access

Records remain locally until you delete them or remove app data. Removing app data or uninstalling can remove your only local vault; export and test recovery first. Deleting a record does not erase it from older encrypted backups or manual exports. Automatic backups aim to keep five encrypted generations; provider history, server snapshots, logs and other copies may retain more.

Disconnecting a provider stops its use but does not promise deletion of remote backups. Revoke Google's access in your Google Account's third-party connections and delete Secrets' hidden app data through Google Drive's app-management controls where available. Revocation alone does not guarantee deletion. Delete SFTP files and server copies through your server administrator; delete exports from their chosen locations. These actions can permanently remove recovery copies.

Analytics, diagnostics and support

Secrets includes no advertising or analytics SDK and no maintainer-operated crash-reporting service. Fixed error categories may appear in device logs; provider response text, passphrases and vault values must not be included in diagnostics. Your operating system and providers may have their own diagnostics policies.

If you open a GitHub issue, GitHub processes your account and submitted content under its policies. Public issues are public. Never submit a real vault, secret, passphrase, provider token, private key or unredacted diagnostic output. Use synthetic examples.

This website and policy changes

This static site is hosted by GitHub Pages. It has no project analytics, forms, external fonts or project cookies. GitHub may process visitor IP addresses and service logs under the GitHub Privacy Statement. Linked external sites apply their own policies.

Changes to this policy will be committed in the public repository with an updated effective date. Forks and modified builds may behave differently; this policy describes the official project.
